# README（产品说明）设计

日期：2026-09-04
状态：已与用户逐节确认

## 背景与目标

仓库（github.com/Ewan-90n9/Friday，公开）一直没有 README。本设计补齐一份**产品说明型 README**：介绍 Friday 当前有什么能力、如何使用、已规划要做的能力。

已确认的决策：

- **读者**：终端用户优先（产品说明），开发构建作为末尾简短章节
- **语言**：仅中文（与 docs/ 现状一致）
- **截图**：实施时运行应用直接截取，不做预留占位
- **使用说明深度**：完整功能手册（非仅快速上手）
- **路线图**：详细路线图（分层展开，不设时间表）
- **结构方案**：单 `README.md` 自包含（方案 A），不拆分 docs/user-guide.md，不用 `<details>` 折叠

预估体量 450-550 行。

## 文档结构总览

```
README.md
├── 1. 头部：logo + 名称 + 一句话定位 + 徽章
├── 2. 主界面截图（1-2 张）
├── 3. Friday 是什么（3 段短文）
├── 4. 核心能力（6 小节，能力矩阵表 + 实现亮点）
├── 5. 安装（Windows 前置要求 + 三步安装）
├── 6. 使用手册（8 小节，操作步骤化）
├── 7. 路线图（已落地 / 下一批 / 远期 三层）
└── 8. 开发构建（命令 + 文档索引，10 行内收尾）
```

章节顺序按用户决策旅程排布（是什么 → 能干什么 → 怎么装 → 怎么用 → 将来 → 开发者），不按代码模块组织。

核心能力（§4）与使用手册（§6）分离：前者面向评估者（表格扫读），后者面向使用者（步骤操作）；同一功能不在两处重复，§6 引用工具时直接用名字。

## 第一屏（§1-§3）

**一句话定位**：

> Friday 是面向软件开发人员的远程环境运行时故障诊断 Agent。输入"环境 + 服务 + 症状"（如 "xx.xx.xx.xx 环境 OOMService OOM 了，帮我定位"），它自动连接目标环境、调用诊断工具、分析根因并给出结论。

**徽章**：`release`（shields.io 动态）+ `platform Windows`。仓库暂无 LICENSE 文件，不加 license 徽章（不在本任务范围内新增 LICENSE）。

**截图**（实施时运行应用截取，存 `docs/assets/`）：

1. 主界面全景（暗色默认主题）：三栏布局完整可见——会话列表、对话流（含工具执行卡片）、工具面板
2. 诊断进行中（可选）：Agent 思考 + 工具卡片 + 传输进度条卡片

**"Friday 是什么"** 三段：

1. 定位与输入输出（你给什么、它还什么）
2. 典型工作流一段话：自动发现环境 → 执行 jvm 工具 → 生成/拉回堆快照 → MAT 分析 → 给结论（用一次 OOM 诊断实例串起来）
3. 设计理念一句：本地 GUI（Tauri），Agent CLI 与诊断引擎全部托管复用，目标机无需安装任何东西

第一屏不放多主题、粒子动效等视觉打磨项（归使用手册）。

## 核心能力（§4）写法

每组能力 = 3-4 行小表格（工具名 / 用途 / 确认级别）+ 1-2 句实现亮点。**工具逐项总表只在 §4 出现一次**，§6 引用工具用名字不再重复。

对用户呈现工具名一律带 `friday_` 前缀（与聊天流、工具面板一致）。

六个小节及要点（数据已从代码核实）：

| 小节 | 内容 | 亮点 |
|------|------|------|
| 4.1 环境连接与命令执行 | SSH 单通道直连（K8s 经 SSH 跑 kubectl）；`run_command` 兜底（高风险强制确认） | 连接按环境池化、空闲 10min 自动断开；凭证存 OS 密钥链 |
| 4.2 JVM 基础诊断 | `list_processes` / `jvm_gc_stats` / `jvm_thread_dump` / `jvm_heap_info` / `jvm_vm_info` / `jvm_class_histogram` / `jvm_heap_dump` | 基于 jstat/jcmd，远程 JDK 检测与版本对齐 |
| 4.3 堆快照分析 | MAT 引擎 9 个 `heap_*`（泄漏疑点/支配树/GC root 链/对象下钻/线程分析） | 快照自动拉回本地、自动建索引预热；会话 LRU |
| 4.4 JFR 飞行记录 | `jfr_record` 定时录制自动拉回 + 21 个 `jfr_*` 分析 | JMC 引擎：规则引擎一键诊断/GC/热点方法/锁竞争/IO/异常/泄漏/A-B 对比 |
| 4.5 Arthas 动态诊断 | 25 个 `arthas_*`（dashboard/thread/watch/trace/sc/jad/ognl 等） | SSH exec 通道 HTTP 桥对接官方 MCP Server，无需目标机 TCP 转发；包随应用分发、SFTP 直传 |
| 4.6 文件传输 | `file_download` / `file_upload` / `transfer_status` / `transfer_cancel` | 专用 SSH 连接后台传输、断点续传、5 次重试/2h 预算、聊天流内进度卡片 |

## 使用手册（§6）内容

按用户生命周期组织，8 小节，操作步骤编号化（① ② ③），穿插 2-3 张补充截图（凭证弹窗 / 工具面板 / 进度卡片各 1 张，实施时截）：

1. **首次启动准备**：装 Agent CLI（opencode 或 codeagentcli，PATH 自动检测 + 手动添加）→ 确认本机 Java 21+（仅 MAT/JMC 需要）→ 添加目标环境与凭证
2. **发起一次诊断**（核心路径，配 1 张截图）：三栏布局一句话 → 新建会话 → 输入症状 → 流式观察 → 获得结论；关键交互：中途停止 / 多轮追问 / 会话切换
3. **环境与凭证管理**：环境 CRUD、多用户凭证、星标默认、逐凭证测试连接、SSH 用户 ≠ JVM 用户时的对齐机制
4. **工具确认与安全边界**：三级风险表（只读自主 / 低风险弹窗 / 高风险强制）+ 免确认模式（附风险提示）
5. **诊断工具面板**：7 组 73 项（环境/JVM/堆快照/JFR/Arthas/文件传输/内置）分组折叠、默认收起、与聊天流同名
6. **文件传输与产物拉回**：手动上传下载 + heap dump/JFR 自动拉回、断点续传、进度卡片、取消
7. **外观与主题**：暗色（默认）/ 浅色 / 暖白，顶栏切换 + 持久化
8. **更新与卸载**：Releases 下载新版覆盖安装

写法约定：不写"背后发生了什么"（引擎托管、会话 LRU、连接池等实现细节归架构文档），只写用户可感知的行为。
